## 卡 1-A：登录改成走真接口（约 30 分钟）

**改哪**：[src/views/Login.vue](<D:/Projects/vue-student-admin/src/views/Login.vue>) 里 `onSubmit()`（第 42–64 行）。

**现在**：第 52 行写死 `if (form.username !== 'admin' || form.password !== '123456')`。

**要变成**：
1. 用 `http.get('/users', { params: { username: form.username, password: form.password } })` 查 json-server 的 `users` 表；
2. 返回是**数组**：`length > 0` 才算登录成功，否则 `ElMessage.error('账号或密码错误')` 并 `return`；
3. 成功时把 `users[0].name` 存进 `localStorage` 的 `userName`（右上角就显示真名字）；
4. 记得在文件顶部 `import http from '../api/http'`。

**易错点**
- json-server 的过滤是**字段精确匹配**，参数名必须和 `db.json` 里的字段一致（`username` / `password`）。
- 既然后端返回的是数组，别再写 `if (res.success)` 这种不存在的判断。
- `loading` 已经有 `finally` 兜底，报错分支也别提前关掉它。

**验收**
- [ ] 密码输错 → 红色提示、不跳转、按钮恢复正常
- [ ] 输对 → 跳到列表页，右上角显示"管理员"
- [ ] 把 `npm run api` 关掉再登录 → 提示"网络异常…"，页面不白屏

**我会追问**：为什么用 GET 查用户而不是 POST？密码明文放 URL 有什么风险？真实项目应该怎么做？

## 卡 2-A：新增 / 编辑保存（约 50 分钟）

**改哪**：[src/views/student/StudentList.vue](<D:/Projects/vue-student-admin/src/views/student/StudentList.vue>) 的 `save()`（第 132–146 行）。

**要变成**
1. 先等校验通过（已有）；
2. 按 `isEdit` 分流：
   - 新增 → `createStudent({ ...form, id: undefined })`（`id` 交给 json-server 生成）
   - 编辑 → `updateStudent(form.id, { ...form })`
3. 成功：`dialogVisible = false` → `await loadData()` → `ElMessage.success('保存成功')`；
4. 失败：**保持弹窗打开**，别把用户填的东西弄丢。

**易错点**
- `Object.assign(form, row)` 会把整行（含 `id`）塞进 `form`，新增时要显式把 `id` 置空。
- 新增后 `rows` 里没有新数据，必须重新 `loadData()`，不要手工 push（会和服务端 ID 对不上）。
- `finally` 里关 `saving`，否则失败后按钮一直转圈。

**验收**
- [ ] 新增一条 → 列表出现，**刷新页面还在**
- [ ] 编辑一条 → 值变了，刷新还在
- [ ] 连点两次保存 → 只产生一条数据
- [ ] 填一半点取消 → 再点新增，表单是空的（`openCreate` 已处理，确认没被 `form` 残留污染）

**我会追问**：为什么新增后要重新拉列表？`PUT` 和 `PATCH` 的区别？如果后端返回 400 你怎么提示？
